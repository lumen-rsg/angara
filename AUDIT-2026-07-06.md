# 🔍 Angara Language — Comprehensive Audit Report

**Date:** 2026-07-06  
**Audit scope:** Full-stack — compiler frontend, type system, Chaperone memory safety, LLVM backend, standard library, tests, build system, CI/CD  
**Version under audit:** v5.1.0 (commits through 4527406)  
**Findings:** 3 Critical · 19 High · 29 Medium · 36 Low  
**Status:** All critical findings resolved. 15 of 19 high findings resolved (H11 investigated — not a bug; H8-H10 deferred). 29 of 29 medium findings resolved or deferred (0 unresolved — all resolved or properly deferred). 34 of 36 low findings resolved or deferred (L21 partially resolved; L8/L11/L22-L24/L30/L35 deferred). 17 findings deferred (architectural or requiring significant effort).

---

## Executive Summary

Angara is a **remarkably ambitious and well-executed** compiler project for a statically-typed systems language. The architecture — recursive-descent parser → type checker → Chaperone memory verifier → LLVM codegen — is clean and coherent. The code is in C++23 with consistent RAII, smart pointers, and proper use of modern patterns.

The initial audit identified 87 findings across all severity levels. **All critical and the majority of high/medium findings have been resolved.** The remaining 17 deferred findings fall into three categories:

1. **Architectural Chaperone improvements** (H8-H10, M11-M13, L22-L24): Per-field ownership tracking, FFI safety annotations, indirect call analysis, concurrency awareness, and flow-sensitive analysis. These require fundamental design changes to the memory safety model. (L21 partially resolved — IIFE and borrowed-argument cases no longer false-positive; L25 fully resolved — flow-sensitive finally analysis.)

2. **Compiler correctness gaps** (M8): Monomorphization-time re-validation of generic bodies. (H11 was investigated and confirmed not a bug — async state machine correctly handles branch awaits.)

3. **Test infrastructure & ecosystem** (M25, M27, L8, L11, L30, L35): Test coverage gaps, missing .an interface files, GC terminology cleanup, async optimization, and platform support. (M17, M18, M19, M21-M24, L25, L34 resolved; L21 partially resolved.)

**Verdict:** v5.1.0 is solid for personal projects and exploration. The critical security vulnerabilities discovered in the standard library C code have been fixed. Production deployment, especially in security-sensitive contexts, should wait until the remaining high-severity deferred findings are addressed.

### Investigated — Not a Bug (1 of 19) 🔍

#### H11. Async State Machine May Incorrectly Resume Across Branches — INVESTIGATED: NOT A BUG
**File:** `TopLevel.cpp:675-677`  

The async lowering assigns linear state numbers to await points. Investigation confirmed this is correct: both the await state collector and codegen use the same DFS order, each await gets a unique state number, and the dispatch switch correctly routes to the appropriate retry_bb in the correct control-flow context. Test `53_async_branch_await.an` verifies awaits in if/else branches, nested branches, and asymmetric branch counts.

**Status:** INVESTIGATED — No bug found. State numbering correctly handles all control-flow patterns.

### Deferred (3 remaining)

#### H8. Field Overwrite Leak — `this.field = x` Silently Leaks Old Field Value — DEFERRED
**File:** `ExprAnalysis.cpp:247` (documented as S6-PARTIAL)  

The Chaperone does not track per-field ownership. When a method reassigns a tracked-type field, the old allocation is **silently leaked** with no diagnostic:
```angara
this.inner = new Buf(1);
this.inner = new Buf(2);  // first Buf LEAKED — no error
drop this;                 // only second Buf is dropped
```

**Status:** DEFERRED — Requires per-field state tracking in the Chaperone, a significant architectural change.

#### H9. FFI Default-Borrow — Unannotated Foreign Functions Cause Silent Double-Free — DEFERRED
**File:** `ExprAnalysis.cpp:347`  

Every foreign/module call without explicit `@consumes`/`@escape` annotations defaults to **Borrow**. A C function like `sqlite3_close(db)` that takes ownership and frees its argument, called without `@consumes(0)`, causes a **silent double-free** — the Angara caller still thinks the argument is Live and may drop it.

**Impact:** Every FFI binding is a potential soundness hole unless meticulously annotated.  
**Status:** DEFERRED — Requires `@consumes`/`@escape` annotation system for foreign functions.

#### H10. Indirect Calls Default to Borrow — Function Pointer Double-Free Undetected — DEFERRED
**File:** `tests/chaperone/positive/18_indirect_call.an` (explicitly documented)  

Calls through function pointers cannot be name-resolved, so the summary defaults to Borrow. If the pointed-to function actually drops, the caller may double-free. The test itself acknowledges this is undetected.

**Status:** DEFERRED — Inherently hard to solve statically; requires runtime checks or restricting function pointers.

## 5. 🏗️ Architectural Observations

### What's Excellent
1. **Pipeline design** — Lexer → Parser → Type Checker → Chaperone → LLVM Codegen is clean and well-separated
2. **Chaperone interprocedural analysis** — Fixed-point convergence algorithm is elegant and proven to terminate in ≤8 passes
3. **FFI design** — `AngaraObject` tagged union, API vtable, `native_instance_new` with finalizers is idiomatic and efficient
4. **Error recovery** — Panic-mode synchronization in the parser is well-implemented
5. **Precedence climbing** — Correct and handles right-associativity (assignment, ternary)
6. **UTF-8 escape processing** — `\u`, `\U`, `\u{...}` handling is thorough, including surrogate rejection
7. **async/await lowering** — Heap-allocated frame struct with waker-based suspension is a solid v1 design
8. **Module ecosystem breadth** — 36 native modules covering a respectable surface area for a young language
9. **Test organization** — Chaperone tests with `// expect: Exxx` headers set a high bar for negative testing
10. **Tree-sitter grammar** — Complete and well-maintained across 755 lines

### What Needs Architectural Work
1. **Chaperone per-field tracking** (H8) — The biggest soundness gap. Reassigning struct fields silently leaks allocations. This is the #1 item to fix for the Chaperone to deliver on its "no leaks" promise.
2. **FFI safety annotations** (H9) — The default-Borrow for all foreign calls is too permissive. A mandatory annotation system or `@nosafe` marker on foreign declarations would close this significant soundness hole.
3. **Division-by-zero checking** ✅ RESOLVED — Runtime checks now emitted before all integer div/mod/shift operations, branching to `__ang_api_throw_error` on invalid operands.
4. **`throw_error` resource leak** (M19) ✅ RESOLVED — Defer mechanism implemented in the LLVM runtime. A thread-local LIFO stack of `{fn, arg}` pairs is drained by `__ang_throw` before `longjmp`. Module authors use `ang_defer(fn, arg)` to register cleanup actions.
5. **Concurrency model** (M11) — The Chaperone has zero concurrency awareness. Before multi-threaded Angara programs become a thing, the ownership model must be extended to cover thread boundaries, `Send`/`Sync`-like traits, and data-race protection.
6. **Async state machine correctness** (H11) ✅ INVESTIGATED — Not a bug. The linear state numbering correctly handles all control-flow patterns (if/else, nested branches, asymmetric await counts). Verified by test `53_async_branch_await.an`.
7. **Test output validation** (M23, M24) ✅ RESOLVED — Inline `// exit: N` and `// stdout:` annotations added to positive tests; `// expect: Exxx` error-code validation added to negative tests.
8. **Channel lifecycle** (M17) ✅ RESOLVED — Atomic refcounting ensures Channel outlives both handles.
9. **Flow-sensitive finally** (L25) ✅ RESOLVED — Recursive `collectGuaranteedDrops()` with guaranteed-execution analysis.
10. **Closure capture false positive** (L21) ✅ PARTIALLY RESOLVED — IIFEs and closures passed as Borrowed arguments no longer trigger E505. Full escape analysis for stored closures still deferred.

## 8. 📝 Methodology

This audit examined the entire Angara codebase (~175 source files, ~15,000 lines) across six independent deep-dive analyses:

1. **Compiler frontend** (lexer, parser): All expression/statement/declaration parsers, token handling, error recovery
2. **Type system & type checker**: Type.h (1000+ lines), SymbolTable, TypeChecker, all expression/statement visitors
3. **Chaperone memory safety**: Full Chaperone.cpp, all expression/statement analysis, all 53 test files, CHAPERONE.md design doc
4. **LLVM codegen backend**: Full LLVMBackend.cpp, all expression/statement codegen, runtime support, async lowering, debug info
5. **Standard library**: All 52 `.c` files across 12 module categories, `Angara.h` FFI header, module Makefile infrastructure
6. **Tests & build system**: All test suites, CI workflow, full Makefile (483 lines), `.clang-tidy`, `.clang-format`

Each analysis was performed independently and cross-referenced for consistency. Findings were classified using a standard severity taxonomy:
- **Critical:** Security vulnerability or data-loss risk exploitable in normal use
- **High:** Correctness bug that produces wrong results, silent data corruption, or unsound safety guarantees
- **Medium:** Bug or limitation that can be triggered in specific scenarios
- **Low:** Code quality issue, cosmetic concern, or enhancement opportunity
