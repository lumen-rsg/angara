## 🟠 High-Severity (3 deferred)

### H8. Field Overwrite Leak — `this.field = x` Silently Leaks Old Field Value
**File:** `ExprAnalysis.cpp:247` (documented as S6-PARTIAL)  

The Chaperone does not track per-field ownership. When a method reassigns a tracked-type field, the old allocation is **silently leaked** with no diagnostic:
```angara
this.inner = new Buf(1);
this.inner = new Buf(2);  // first Buf LEAKED — no error
drop this;                 // only second Buf is dropped
```

**Status:** DEFERRED — Requires per-field state tracking in the Chaperone, a significant architectural change.

### H9. FFI Default-Borrow — Unannotated Foreign Functions Cause Silent Double-Free
**File:** `ExprAnalysis.cpp:347`  

Every foreign/module call without explicit `@consumes`/`@escape` annotations defaults to **Borrow**. A C function like `sqlite3_close(db)` that takes ownership and frees its argument, called without `@consumes(0)`, causes a **silent double-free** — the Angara caller still thinks the argument is Live and may drop it.

**Impact:** Every FFI binding is a potential soundness hole unless meticulously annotated.  
**Status:** DEFERRED — Requires `@consumes`/`@escape` annotation system for foreign functions.

### H10. Indirect Calls Default to Borrow — Function Pointer Double-Free Undetected
**File:** `tests/chaperone/positive/18_indirect_call.an` (explicitly documented)  

Calls through function pointers cannot be name-resolved, so the summary defaults to Borrow. If the pointed-to function actually drops, the caller may double-free. The test itself acknowledges this is undetected.

**Status:** DEFERRED — Inherently hard to solve statically; requires runtime checks or restricting function pointers.

## 🟡 Medium-Severity (5 deferred)

### Chaperone

#### M11. No concurrency/async awareness — double-free possible in multi-threaded code
**Location:** Chaperone design  

The Chaperone has zero concurrency awareness. Before multi-threaded Angara programs become viable, the ownership model must be extended to cover thread boundaries, `Send`/`Sync`-like traits, and data-race protection.

**Status:** DEFERRED — Architectural change to the Chaperone's interprocedural analysis.

#### M12. `ref<T>` borrows through `data` struct fields untracked — dangling ref
**Location:** `ExprAnalysis.cpp`  

When a `ref<T>` is taken to a field of a `data` struct, the Chaperone does not track the borrow through the struct indirection. This can result in a dangling reference if the struct is dropped while the ref is still live.

**Status:** DEFERRED — Requires per-field borrow tracking in the Chaperone.

#### M13. Generic type parameters may not resolve before monomorphization
**Location:** `ExprAnalysis.cpp`  

The Chaperone runs before monomorphization, so it cannot analyze ownership for generic type parameters whose concrete types are unknown. Some generic functions may pass the Chaperone but produce unsound monomorphized code.

**Status:** DEFERRED — Requires either monomorphization-before-Chaperone or bounded parametric analysis.

### Testing & CI

#### M25. No type-checker, Chaperone, or codegen unit tests in C++ suite
**Location:** `tests/cpp/`  

The C++ test suite only covers the lexer and parser fuzzer. There are no unit tests for the type checker, Chaperone memory analysis, or LLVM codegen — making regression prevention dependent entirely on integration-level language tests.

**Status:** DEFERRED — Significant test writing effort required.

#### M27. Fuzz only covers lexer/parser, not type checker or codegen
**Location:** `tests/cpp/test_fuzz.cpp`  

The fuzz harness feeds random bytes to the lexer and parser, but doesn't exercise the type checker, Chaperone, or codegen — where more subtle bugs are likely to hide.

**Status:** DEFERRED — Test infrastructure enhancement needed.

## 🔵 Low-Severity (8 deferred)

### Compiler

- **L8.** All async locals boxed as full `AngaraObject` (128-bit), even `i64` counters (`TopLevel.cpp:386-414`). DEFERRED: architectural change to allow unboxed async locals for small types.

- **L11.** GC terminology persists throughout the codebase despite v5 garbage collector removal (cosmetic). ACKNOWLEDGED: full rename touches ~50 call sites for no functional benefit.

### Chaperone

- **L21.** Closure capture always Escaped (E505) even for synchronous-only use — false positive. **PARTIALLY RESOLVED:** IIFE (immediately-invoked function expressions) and closures passed as arguments to functions that Borrow the parameter are now detected and no longer trigger E505. Full escape analysis for closure variables stored in locals still deferred.

- **L22.** Container cycles (e.g., `list<B>` where `B → A`) not detected as E504. DEFERRED: architectural — requires cycle detection in the Chaperone's escape analysis.

- **L23.** Return of tracked value as `ref<T>` incorrectly treated as ownership escape. DEFERRED: architectural — requires distinguishing returning-a-ref from escaping-ownership.

- **L24.** Loop-post-dominance false positive — conservative Live-after-loop. DEFERRED: architectural — the Chaperone conservatively marks values as Live after loops even when the loop always drops them.

### Standard Library & Ecosystem

- **L30.** Missing `.an` interface files for most modules (only 3 originally). **PARTIALLY RESOLVED:** Interface files written for 6 key modules (io, fs, math, net, time, json) in `docs/interfaces/`. Full type-checked integration requires compiler support for native-module interface forwarding (`.an` → `.so` linkage). Remaining ~27 modules still need interface files.

- **L35.** No Windows build support at all. DEFERRED: platform support — the codebase is Linux + macOS only, with no Windows build system, platform abstractions, or CI coverage.

## 📝 Methodology

This audit examined the entire Angara codebase (~175 source files, ~15,000 lines) across six independent deep-dive analyses:

1. **Compiler frontend** (lexer, parser): All expression/statement/declaration parsers, token handling, error recovery
2. **Type system & type checker**: Type.h (1000+ lines), SymbolTable, TypeChecker, all expression/statement visitors
3. **Chaperone memory safety**: Full Chaperone.cpp, all expression/statement analysis, all 53 test files, CHAPERONE.md design doc
4. **LLVM codegen backend**: Full LLVMBackend.cpp, all expression/statement codegen, runtime support, async lowering, debug info
5. **Standard library**: All 52 `.c` files across 12 module categories, `Angara.h` FFI header, module Makefile infrastructure
6. **Tests & build system**: All test suites, CI workflow, full Makefile (483 lines), `.clang-tidy`, `.clang-format`

Each analysis was performed independently and cross-referenced for consistency. Findings were classified using a standard severity taxonomy:
- **Critical:** Security vulnerability or data-loss risk exploitable in normal use
- **High:** Correctness bug that produces wrong results, silent data corruption, or unsound safety guarantees
- **Medium:** Bug or limitation that can be triggered in specific scenarios
- **Low:** Code quality issue, cosmetic concern, or enhancement opportunity
